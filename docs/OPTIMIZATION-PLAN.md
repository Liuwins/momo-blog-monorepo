# MomoBlog 分阶段优化计划

状态：2026-08-21，计划基于公开快照 `aabe711` 制定；阶段 1 代码已在本地完成并通过静态构建与临时 SQLite migration 验证，尚未推送公开仓库。

本文用于安排后续工程优化，不代表所有项目已经完成。每个阶段都应先完成代码、验证和文档，再进入下一阶段；没有通过验收标准的阶段不标记为完成。

## 执行原则

1. 一个阶段对应一个可审阅的 Monorepo 提交；前后端联动功能不拆成两个远程提交。
2. 修改数据库实体时，必须同时提交 TypeORM migration 和迁移验证记录。
3. 先修数据正确性和安全边界，再做性能、体验和非必要功能；避免在缺少回归保护时扩大改动范围。
4. 生产环境验证与本地构建验证分开记录。构建通过不等于部署、WebSocket、上传或恢复演练通过。
5. 公开仓库不提交 `.env`、数据库、上传文件、日志、截图、依赖和构建产物；部署值通过环境变量或服务器密钥管理注入。
6. 每个阶段结束时更新 `ROADMAP.md`、`PROJECT-WIKI.md` 或 `docs/DEPLOYMENT.md` 中受影响的说明。

- 后端：NestJS + TypeORM + better-sqlite3，默认端口 `3001`；typecheck、build 已通过。

## 阶段 0：基线与发布治理

目标：让后续优化可回滚、可审阅、可定位。

任务：

- 在 GitHub 建立 issue/PR 模板，要求填写影响范围、验证命令、迁移和回滚说明。
- 确认源仓库只做归档，不删除、不继续接收业务提交；在源仓库 README 增加 Monorepo 链接（需单独确认后操作）。
- 增加变更日志或 release 约定；公开发布只从 `master` 产生。
- 确认敏感文件扫描和快照检查命令可在本地重复执行。

验收：

- 新贡献者可以从根 README 找到开发、部署、路线图和优化计划入口。
- 任一提交都能说明属于哪个阶段，并能通过 `git revert` 回滚。

## 阶段 1：数据正确性与安全边界（最高优先级）

目标：先消除已经确认的功能缺口和生产误配置风险。

任务：

- 完整接入动态 `music`：`PostsService.create/update/findAll/findById`、个人动态查询、前端回填和序列化保持一致。
- 为 `images`、`videos`、`tags` 增加数组元素类型、单项长度和 URL/路径约束；限制分页参数的最小值、最大值和类型。
- 生产环境拒绝缺失或非 `production` 的关键配置；确保 `synchronize` 不会因环境变量拼写错误而开启。
- 将 Open Graph 站点地址改为环境变量，避免代码绑定某个真实域名。
- Docker Compose 后端端口默认只绑定本机或不映射到宿主机，由前端 Nginx/内部网络访问。
- 审核上传、评论、动态删除和媒体引用的权限边界；补充异常输入和未认证访问的明确错误响应。

验收：

- 创建、编辑、首页、详情和个人页都能保存并返回同一个 `music` 值。
- 生产配置错误会在启动时失败并给出明确提示；生产日志不输出密码、Token 或密钥。
- 后端 `3001` 无公网暴露路径，API 只能通过预期代理访问。
- 完成一次可回放 migration，并记录备份与回滚步骤。

阶段 1 本轮额外修复了公开快照中重复初始化 migration 导致的空库失败：保留原迁移名称并将重复项改为兼容性 no-op，避免已存在表被重复创建。

## 阶段 2：核心测试与 CI

目标：把阶段 1 的关键行为固定成自动化门禁。

任务：

- 后端补 Auth、Posts、Comments、Upload、Migration 的单元/集成测试。
- 前端补请求拦截器、用户会话恢复、路由守卫、发布和评论交互测试。
- 为 WebSocket 鉴权、上传大小/MIME、游客评论、管理员审核增加至少一条回归用例。
- 在 GitHub Actions 中执行：锁文件安装、前端 lint/test/build、后端 typecheck/build、敏感文件扫描。
- 测试命令缺少测试文件时不应掩盖配置错误；测试目录建立后移除仅为“无测试通过”设置的宽松行为。

当前进度（2026-08-21）：

- 已完成前端 Vitest 配置；
- 已覆盖全局背景音乐状态、跨路由不重复加载、发布页未登录拦截和有效会话放行，共 5 条测试；
- 已新增 `.github/workflows/ci.yml`，执行前端 lint/test/build 与后端 test/typecheck/build，尚未在 GitHub 远程运行环境验收；
- 后端已补 Auth、Posts、Comments、Upload、WebSocket、Migration、Health 和 DTO 核心业务回归测试（17 条）；本地测试、类型检查和构建已通过，远程 CI 尚未验收。
- CI 已增加公开仓库敏感/生成文件扫描和 Compose 插值校验；远程 CI 尚未验收。

验收：

- PR 在 CI 全部通过后才允许合并。
- 关键 API 至少有成功、未认证、越权、非法输入四类断言。
- CI 不读取生产凭据，不上传数据库或构建产物。

## 阶段 3：部署可靠性与可恢复性

目标：从“能构建”推进到“可安全部署和恢复”。

任务：

- 已补 Compose healthcheck、启动顺序、迁移失败处理和日志查看说明；临时 Docker 后端已验证 migration 与 `/api/health`。
- 在临时环境完成 `/api/health`、SPA、API、图片、上传和 Socket.IO 代理验证。
- 已增强备份脚本：使用 SQLite 一致性备份并将上传目录单独归档；已在隔离 Alpine 容器完成数据库完整性与媒体文件恢复演练，目标部署机仍需按实际存储路径复演。
- 已完善媒体清理脚本的引用扫描，覆盖图片、视频、动态配乐、头像、封面和背景音乐；保持默认只报告。
- 校验 Nginx 上传上限、HTTPS、CORS、Cookie、反向代理和后端暴露面。

验收：

- 新机器按 `docs/DEPLOYMENT.md` 可以完成部署，不依赖个人绝对路径或本机配置。
- 删除并恢复临时数据库和上传目录后，站点数据和媒体引用一致。
- WebSocket 与大文件上传均有真实请求验证记录。

阶段 3 当前进度：Compose 配置校验、后端生产镜像构建、临时数据库迁移和健康检查已通过；备份脚本已生成数据库与媒体成对归档，并完成隔离恢复完整性演练；完整前端容器因本机 80 端口被其他项目占用未启动，真实域名、WebSocket、上传和目标部署机恢复仍未验证。

## 阶段 4：查询性能与资源治理

目标：在正确性和测试稳定后，降低数据量增长带来的性能风险。

任务：

- 优化动态列表的 N+1 查询：点赞状态、评论预览和点赞用户改为批量查询或合理关联。
- 为高频过滤和排序字段评估 SQLite 索引，使用真实数据量做查询计划对比。
- 统一分页上限、排序白名单、关键词长度和标签查询策略，避免无限查询和低效模糊匹配。
- 统计上传文件大小、类型、失败率和清理候选，避免媒体目录无限增长。
- 对通知、评论计数和点赞计数的并发一致性增加事务或幂等保护。

验收：

- 公开首页和个人页在代表性数据集下的查询次数、响应时间和内存占用有前后对比。
- 所有性能改动都有回归测试，不改变公开 API 响应结构。

## 阶段 5：移动端体验与可访问性

目标：改善真实手机使用中的输入、反馈和可访问性。

任务：

- 修复软键盘弹出时评论输入框、发布编辑器和上传进度的可见性。
- 检查加载、空状态、错误、成功、离线和重连状态的文案与操作路径。
- 完善键盘焦点、ARIA 标签、颜色对比、触摸目标尺寸和 reduced-motion 支持。
- 使用真实移动视口完成首页、详情、发布、登录、通知和个人页冒烟测试。

验收：

- 主要任务在移动视口下可完成，不依赖桌面专属交互。
- 无阻断级浏览器控制台错误；关键表单和按钮可通过键盘或辅助技术定位。

## 阶段 6：可选增强

- 更细粒度的评论回复通知；
- CSP nonce、更严格的媒体内容校验和安全审计；
- 公开版本号、变更日志和可重复发布流程。
